## CORREÇÃO 1: TTS fala "dois estrelas" em vez de "duas estrelas"

### 📍 Problema
O TTS do Android lê números como masculinos por padrão. Ao dizer "Você ganhou 2 estrelas!", o TTS pronuncia "dois estrelas" em vez de "duas estrelas".

### 📂 Arquivo a alterar
`app/src/main/java/com/pequenospassos/presentation/screens/completion/TaskCompletionScreen.kt`

### 🔍 Código atual (linhas ~95-97)
```kotlin
// Refinamento Fase 6: Mensagem de estrelas ganhas
val starsText = if (stars == 1) "estrela" else "estrelas"
val ttsMessageStars = "Você ganhou $stars $starsText!"
```

### ✅ Correção proposta
Substituir o número inteiro pelo número por extenso no feminino:

```kotlin
// Correção v2.5.1: Concordância de gênero feminino para TTS
val starsText = if (stars == 1) "estrela" else "estrelas"
val starsNumber = when (stars) {
    1 -> "uma"
    2 -> "duas"
    3 -> "três"
    4 -> "quatro"
    5 -> "cinco"
    else -> "$stars"  // fallback para números maiores
}
val ttsMessageStars = "Você ganhou $starsNumber $starsText!"
```

### 🧪 Como testar
1. Executar qualquer tarefa até o final
2. Na tela de conclusão, ouvir o TTS
3. Deve falar "Você ganhou **duas** estrelas" (não "dois")
4. Testar com 1 estrela: "Você ganhou **uma** estrela"

### 📝 Após implementar
- Incrementar versão para 2.5.1 no `build.gradle.kts` e `SplashScreen.kt`
- Atualizar CHANGELOG.md
- Compilar: `.\compilar_e_testar.bat`

## CORREÇÃO 2: TTS repete frase ao mudar rotação do dispositivo

### 📍 Problema
Ao girar o celular (portrait ↔ landscape), o Compose recria a tela e o `LaunchedEffect(Unit)` dispara novamente, fazendo o TTS repetir toda a frase.

Afeta duas telas:
- **TaskCompletionScreen** — repete parabéns ao rotacionar
- **TaskExecutionScreen** — repete instrução do passo ao rotacionar

### 📂 Arquivos a alterar

**Arquivo 1:** `TaskCompletionScreen.kt`

**Código atual:**
```kotlin
LaunchedEffect(Unit) {
    visible = true
    kotlinx.coroutines.delay(500)
    val ttsMessageCongrats = ...
    ttsManager.speak(ttsMessageCongrats)
    ttsManager.speakQueued(ttsMessageSuccess)
    ttsManager.speakQueued(ttsMessageStars)
}
```

**Correção:** Usar `rememberSaveable` para controlar se TTS já foi executado:
```kotlin
var ttsAlreadySpoken by rememberSaveable { mutableStateOf(false) }

LaunchedEffect(Unit) {
    visible = true
    if (!ttsAlreadySpoken) {
        kotlinx.coroutines.delay(500)
        val ttsMessageCongrats = ...
        ttsManager.speak(ttsMessageCongrats)
        ttsManager.speakQueued(ttsMessageSuccess)
        ttsManager.speakQueued(ttsMessageStars)
        ttsAlreadySpoken = true
    }
}
```

**Arquivo 2:** `TaskExecutionScreen.kt` (ou `TaskExecutionViewModel.kt`)

**Abordagem:** No ViewModel, manter um `lastSpokenStepIndex` que evita repetir TTS para o mesmo passo:
```kotlin
// No ViewModel
private var lastSpokenStepIndex: Int = -1

fun markStepAsSpoken(stepIndex: Int) {
    lastSpokenStepIndex = stepIndex
}

fun shouldSpeakForStep(stepIndex: Int): Boolean {
    return stepIndex != lastSpokenStepIndex
}
```

Na Screen, verificar antes de chamar TTS:
```kotlin
LaunchedEffect(state.currentStepIndex) {
    if (viewModel.shouldSpeakForStep(state.currentStepIndex)) {
        ttsManager.speak(...)
        viewModel.markStepAsSpoken(state.currentStepIndex)
    }
}
```

### 🧪 Como testar
1. Abrir uma tarefa e iniciar execução
2. Girar o celular durante um passo
3. O TTS **não** deve repetir a instrução
4. Concluir a tarefa → tela de parabéns
5. Girar o celular na tela de parabéns
6. O TTS **não** deve repetir "Parabéns"

## CORREÇÃO 3: Imagem não exibe ao mudar rotação para landscape

### 📍 Problema
Ao rotacionar o dispositivo para landscape durante a execução de um passo, a imagem do step desaparece. O layout provavelmente não se adapta à orientação horizontal.

### 📂 Arquivo a alterar
`app/src/main/java/com/pequenospassos/presentation/screens/taskexecution/TaskExecutionScreen.kt`

### 🔍 Investigação necessária
Antes de implementar, verificar:
1. Se o `AsyncImage` usa `fillMaxWidth()` sem limitar altura
2. Se há `Column` sem scroll que estoura o espaço em landscape
3. Se a imagem tem `contentScale` adequado

### ✅ Correção proposta

**Opção A — Tornar o conteúdo scrollável:**
```kotlin
// Envolver conteúdo em scroll para landscape
val scrollState = rememberScrollState()
val configuration = LocalConfiguration.current
val isLandscape = configuration.orientation == Configuration.ORIENTATION_LANDSCAPE

Column(
    modifier = Modifier
        .fillMaxSize()
        .verticalScroll(scrollState)  // ADICIONAR SCROLL
) {
    // ... conteúdo existente
    
    // Ajustar tamanho da imagem em landscape
    if (state.currentStep?.imageUrl != null) {
        AsyncImage(
            model = state.currentStep?.imageUrl,
            contentDescription = "Imagem do passo",
            modifier = Modifier
                .fillMaxWidth()
                .heightIn(max = if (isLandscape) 200.dp else 300.dp),  // LIMITAR EM LANDSCAPE
            contentScale = ContentScale.Fit
        )
    }
}
```

**Opção B — Layout adaptativo:**
```kotlin
if (isLandscape) {
    // Em landscape: imagem à esquerda, controles à direita
    Row(modifier = Modifier.fillMaxSize()) {
        // Imagem ocupa metade da tela
        AsyncImage(..., modifier = Modifier.weight(1f))
        // Controles na outra metade
        Column(modifier = Modifier.weight(1f)) { ... }
    }
} else {
    // Em portrait: layout vertical normal
    Column { ... }
}
```

**Recomendação:** Opção A é mais simples e segura. Opção B é melhor UX mas mais complexa.

### 🧪 Como testar
1. Abrir uma tarefa que tenha imagem em algum passo
2. Executar até o passo com imagem
3. Verificar que imagem aparece em portrait
4. Girar para landscape
5. A imagem deve continuar visível (com scroll se necessário)
6. Girar de volta para portrait — tudo normal

## CORREÇÃO 4: App permite avanço imediato de vários passos

### 📍 Problema
O usuário pode tocar rapidamente no botão de avançar e pular vários passos de uma vez. O ideal é ter uma proteção (debounce) e opcionalmente uma confirmação via TTS.

### 📂 Arquivos a alterar
- `TaskExecutionViewModel.kt` — lógica de debounce
- `TaskExecutionScreen.kt` — desabilitar botão temporariamente

### ✅ Correção proposta

**Passo 1 — Debounce no ViewModel:**
```kotlin
// No ViewModel
private var lastAdvanceTime: Long = 0L
private val ADVANCE_DEBOUNCE_MS = 1500L  // 1.5 segundos entre avanços

fun canAdvanceToNextStep(): Boolean {
    val now = System.currentTimeMillis()
    if (now - lastAdvanceTime < ADVANCE_DEBOUNCE_MS) {
        return false
    }
    lastAdvanceTime = now
    return true
}
```

**Passo 2 — Na Screen, desabilitar botão enquanto TTS fala:**
```kotlin
val isSpeaking by ttsManager.isSpeaking.collectAsState()

Button(
    onClick = {
        if (viewModel.canAdvanceToNextStep()) {
            viewModel.moveToNextStep()
        }
    },
    enabled = !isSpeaking  // Desabilitar enquanto TTS fala
) {
    Text("Próximo Passo")
}
```

**Passo 3 (Opcional) — Confirmação via TTS para avanço rápido:**
Se o usuário tentar avançar antes do timer acabar, o TTS pode perguntar:
```kotlin
fun requestAdvance() {
    if (remainingTimePercent > 0.5f) {
        // Mais de metade do tempo restante — confirmar
        ttsManager.speak("$childName, você realmente já terminou?")
        // Mostrar dialog de confirmação
        _showConfirmAdvanceDialog.value = true
    } else {
        // Menos da metade — avançar direto
        moveToNextStep()
    }
}
```

### 🧪 Como testar
1. Iniciar uma tarefa com vários passos
2. Tocar rapidamente várias vezes no botão "Próximo"
3. Deve avançar **apenas 1 passo** (debounce)
4. Aguardar 1.5s e tocar novamente — deve avançar normalmente
5. (Se implementou confirmação) Tentar avançar com >50% do tempo → deve perguntar
